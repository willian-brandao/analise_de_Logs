## Introdução 

Windows e Linux são dois sistemas operacionais amplamente usados, e cada um tem sua própria infraestrutura para gerar, guardar e consultar logs. Para analistas de segurança. entender as diferenças é fundamental para criar uma abordagem coersistiva para monitorar, detectar de ameaçar e responder incidentes. 

---

## Estruturas e Formatos Diferentes
|            Aspecto                   |             Linux                   |         Windows                              |
|--------------------------------------|-------------------------------------|----------------------------------------------|
| Formato de Logs                      |   Texto(syslog), CSV, JSON          | Binário (EVTX), XML (em algumas ferramentas) |
| Localização de Armazenamento         |   /var/log/                         | %SystemRoot%\System32\winevt\Logs\           |
| Método de acesso                     | Ferramentas de CLI (grep,journalctl | GUI(Event Viewer), Powershell                |
| Rotação de Logs                      | Gerenciamento por rotação de logs   | Sobrescrita automática ou arquivos manuais   |
| Timestamps                           | Legível por humanos / UTC           | UTC com contexto de tempo local              |
| Ferramentas de auditoria customizadas| auditd, syslog-ng, rsyslog          | Politicas de auditoria avançadas, sysmon     |

---

## Comparação de Registro de Logs 

|         Cenário                      |            Linux Log                                |        Windows Log              |
|--------------------------------------|-----------------------------------------------------|---------------------------------|
| Login com Sucesso (local/SSH)        | Senha aceita por usuário com IP de origem           | 4624 (Login com sucesso )       |
| Falha no Login                       | Senha falhou para usuário inválido com IP de origem | 4625 (Falha no Login)           
| Escalonamento de Privilégio          | sudo: user: COMMAND=/bin/bash                       | 4672 (assinatura de privilégios de administrador), 4688(execução de comandos |
| Acesso Remoto                        | sshd: sessão aberta pelo usuário com ip de origem   | 4624 (Login tipo 10 - RDP)      |
| Logoff                               | sessão fechada para usuário                         | 4634 (logoff)                   |

*Observation: Enquanto os logs do linux tipicamente usam linhas simples, legíveis, os logs do Windows oferecem metadados ricos porém que requerem ferramentas para decodificar o formato binário .evtx.*

---

## Comparação de Execução de Processo

|            Evento            |            Linux(auth.log ou auditd)            |      Windows(Event Viewer ou Sysmon       |
|------------------------------|-------------------------------------------------|-------------------------------------------|
| Criação de processo          |   auditd: execve("/bin/bash",...)               | 4688: New Process Created                 |
| Parâmetros de comando        |   auditd ou histórico do shell(bash history)    | 4688 + linha de comando (se permitido via política |
| Rastreio de execução de arquivo | Não é padrão; requer auditd ou inotify       | Sysmon Event Id 1 (Process Create)        |
| Identificação de processo pai| Manualmente via "ps -ef --forest" ou logs de auditoria | Disponível em 4688 e Sysmon        |

---

## Acesso de Arquivo e Modificação de Registro de Log 

|          Ação                         |             Linux                      |            Windows                      |
|---------------------------------------|----------------------------------------|-----------------------------------------|
| Leitura/escrita/abertura/deleção de arquivo | requer auditd ou fanotify        | Sysmon (Event id 11, 23)                |
| Localização de Logs                   | /var/log/audit/audit.log               | Sysmon ou EDR terceiro                  |
| Registro de mudanças de registro de logs | não aplicável                       | Sysmon Event id 13 ( Registry Set Value) |

**Insight:** Linux requer configuração explícita( auditd, incron, regras de auditoria) para gerar logs que são similares em granularidade ao que Windows provê nativamente via Sysmon ou Políticas de auditoria de grupos de políticas.

## Visibilidade de Logs e Cobertura 

|            Área             |               Cobertura de Linux               |           Cobertura Windows          |
|-----------------------------|------------------------------------------------|--------------------------------------|
| Eventos de autenticação     |  Forte via auth.log, btmp                      | Forte via log de segurança           |
| Atividade de processo       |  Forte por padrão, forte via auditd            | Moderado por padrão, forte via Sysmon|
| Atividade de Rede           |  Fraco, requer IPTables, Suricata              | Fraco, requer sysmon ou ferramentas baseadas em ETW |
| Acesso de sistema de arquivos | Requer auditd ou fanotify                    | Suportado via sysmon                 |
| Detecção de script de execução| Manual ou via auditd                         | via 4688 e registro de log no Powershell |
