## Introdução 

Logs de eventos são um dos pilares da visibilidade nos ambientes Microsoft. Todas as atividades relevantes de segurança, assim como autenticação, criação de processo, mudança de privilégio, e conexões remotas, é registrado nativamente pelo sistema operacional. A habilidade para interpretar eventos críticos específicos para detectar ataques como de força bruta, uso de malware, execução de comandos administrativos ou persistência através de escalonamento de privilégio. 

---

## Tipos de Eventos de Log do Windows

Windows classifica os logs em três categorias:

* Logs de Sistemas - informação sobre drives, falhas de hardware e serviços de sistemas operacionais.
* Logs de Aplicação - eventos gerados por softwares instalados no sistema (ex: SQL Server, Office, Chrome).
* Logs de Segurança - foco principal para analistas de segurança. Contém autenticação, mudanças de contas, criação de processo, uso de credenciais, entre outros.

*Acesso via Event Viewer: start>run>eventvwr.msc*

## Id de Eventos Chaves para Analistas de Blue Team
| Id do Evento                 | Descrição                                     | Caso de Uso                                       |
|------------------------------|-----------------------------------------------|---------------------------------------------------|
| 4624                         | Login com sucesso                             | RDP, SMB, logins programados ou interativos       |
| 4625                         | Login falho                                   | Tentativa de força bruta ou credenciais inválidas |
| 4634                         | Evento de logoff                              | Encerramento de sessão                            |
| 4648                         | Logon usando credenciais explícitas           | Movimento lateral (runas, PSRemoting              |
| 4672                         | Privilégios especiais atribuídos ao novo login| Acesso de admin no sistema                        |
| 4688                         | Nova criação de processo                      | 

### Exemplo> Login com Sucesso (4624)
```
Log Name: Security  
Event ID: 4624  
Logon Type: 10 (RemoteInteractive)  
Account Name: administrator  
Source Network Address: 192.168.1.100
```
*Interpretação:* O administrador se autenticou com sucesso via RDP do IP: 192.168.1.100.

Tipos de login ( usados comumente para lógica de detecção):

* 2 = Interativa (local)
* 3 = Redes (SMB, CIFS)
* 5 = Serviços
* 10 = Desktop remoto
* 11 = Interativo em cache.

### Exemplo: Login Falho(4625)*
```
Event ID: 4625  
Failure Reason: Unknown user name or bad password  
Logon Type: 3  
Account Name: admin  
Source Network Address: 10.10.10.5
```

**Interpretação:**
Tentativa de login falho, provável smb ou acesso de diretório compartilhado.

Caso de Uso:
Detecção de tentativa de movimento lateral ou ataque de força bruta. 

### Exemplo: Processo de Criação (4688)

```
Event ID: 4688
New Process Name: C:\Windows\System32|WindowsPowershell\v1.0\powershell.exe
Comand Line: powershell.exe -EncondedCommand SQBtAGUAbABvAGcA
```
Caso de Uso: A flag da linha de comando do Powershell com conteúdo codificado em base64. Comum na execução de malware e em scripts evasivos.

## Casos de Uso Comuns de Detecção 

**Caso de Uso 1: Ataque de força bruta RDP**

  - Muito registros de eventos 4625 seguidos de eventos com registro 4624 com tipo de logon 10.
  - Correlação:
     - O IP de origem permanece o mesmo.
     - Os nomes de usuário variam.
     - O intervalo de tempo é curto. Média de 5 minutos.

**Caso de Uso 2: Execução de ferramenta suspeita**
* 4688 para *cmd.exe*, *powershell.exe*, *mshta.exe*, *rundll32.exe*.
* Correlacionar com processo parental para detectar origens não usuais.
* Linha de comando pode ser analisada e inspecionada em busca de conteúdo codificado.

**Caso de Uso 3:Movimento Lateral via Credenciais Explicítas.**
* *4648* com sistemas alvo suspeitos.
* Exemplo: Atacantes usam *runas* ou invocam *Invoke-Command* sobre o WinRM.

**Caso de Uso 4: Persistência via Serviço  de Instalação**

* *4697* seguido por *4624* indicando execução.
* Serviços com nomes ou arquivos não usuais (ex: no diretório temp).

## Filtrando e Analisando Logs para Detecção 

Ao encaminhar a um SIEM, é recomendável extrair e normalizar os campos-chave:

* EventID
* AccountName
* LogonType
* ProcessName
* ParentProcessName
* SourceNetworkAddress

**Exemplo: Pesquisa SPL no Splunk**
```
index=windows EventCode=4688
| stats count by New_Process_Name, Parent_Process_Name
| where count > 5 
```
**Exemplo: SIEM Elastic(KQL)**
```
event.code: "4625" and source.ip:  "192.168.1.10"
```

## Melhores Práticas

* Permitir política de auditoria avançada (  Criação de Auditoria de Processo, Auditoria de Eventos de Logon)
* Configurar a política de grupo para incluir registro de linhas de comando:
  * Administrative Templates > System > Audit Process Creation > Include command Line in process creation events
* Reter pelo menos 90-180 dias de logs de segurança.evtx.
* Usar Sysmon juntamente com os logs nativos para obter telemetria mais detalhada (por exemplo, gravaçõe de arquivos, acesso ao registro).

###Técnica 1: Detectar Credenciais de Acesso e Escalonamento de Privilégio

Correlacionar Id do Evento 4648 (credenciais explícitas) com 4628 (logon) e 4672 ( privilégios de admin)

Caso de Uso: Atacante executando serviços como *runas*, *PsExec*, ou *Invoke-Command* sobre o WinRM frequentemente gera esses tipos de eventos.

Exemplo de Sequência:
```
Event ID 4648: A logon was attempted using explicit credentials.
Event ID 4628: Successful logon ( Logon Type 3 ou 10).
Event ID 4672: Special privileges assigned (ex: SeDebugPrivilege)
```
Lógica de Detecção: 
* Rastrear uso raro do Id de Evento 4648.
* Referência cruzada de nome de conta e IP de Origem.
* Confirmar se a conta usada recebeu privilégios elevados (4672)
---
###Técnica 2: Procurar por Execuções Maliciosas no Powershell

Indicadores em 4688 (criação de processo)
* Uso do **powershell.exe** ou **pwsh.exe**.
* *-EncodedCommand.*
* *-WindowsStyle hidden*, **-nop**, **-exec bypass**.
* Comandos de Download: **Invoke-WebRequest**, **System.Net.WebClient**

#### Exemplo vindo do Event Viewer:
```
New Process Name: C:\Windows\System32\WindowsPowershell\v1.0\powershell.exe
Command Line: powershell.exe -nop -w hidden -EncodedCommand SQBtAGUAbABvAGcA
```
#### Pista de procura:
```
Get-WinEvent -FilterHashTable @{LogName='Security'; Id=4688} |
Where-Object { $_.Message -match "powershell.*EncodedCommand"} |
Format-Table TimeCreated, Message -AutoSize
```

*Mapear ao  MITRE ATT&CK T1059.001 ( Comando e Interpretador de Scripting: Powershell)*
---

#### Técnica 3: Detectar Processo de Injeção e Evasão 

**Indicadores:**

* Uso suspeito de *rundll32.exe*, *regsvr32.exe*, *mshta.exe*.
* Processo pai incomuns como *exeplore.exe*  , executando *cmd.exe* ou *powershell.exe*.
* Execução direta vinda do *AppData*, *Temp*, ou caminhos de ISO montados.

*Exmplo:*
```
4688: New Process Name: C:\Users\user\AppData\Local\Temp\evil.exe
Parent Process Name: C:\Windows\explorer.exe
```
*Detection:*
* Destacar binários não assinados executados a partir de caminhos graváveis pelo usuário.
* Olhar por erros no comportamento em processos  pai/filhos.
