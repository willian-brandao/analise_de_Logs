Como sistemas e aplicações rodando continuamente, logs podem crescer rapidamente e consumem espaço de disco significante se não gerenciados propriamente. Logs não com crescimento incontrolável podem levar à instabilidade em sistemas, perda de dados, ou na inabilidade de reter eviências importantes. Profissionais de Blue Team devem entender e implementar rotação de logs e estratégias de retenção para assegurar performance, disponibilidade e comformidade de segurança.

Rotação de logs referecem ao processo de arquivar, comprimir e deletar logs de arquivos antigos depois de um intervalo de tempo específico ou quando o tamanho do limite é alcançado. Políticas de detenção definem qual o tamanho dos logs podem ser armazenados e quais logs são críticos para se preservar para audições, detecções ou investigação. 

## Por que gerenciamento de log é crítico?

1. Controle de Espaço de Disco

   Prevenir que logs enchendo o disco e quebrando serviços.

3. Preservação Forense
    
   Assegurar que evidências chave estão disponíveis durante uma investigação de incidente.

4. Conformidade

   Muitos frameworks(ex: PCI-DSS, HIPAA, ISO 27001) requer que logs sejam retidos por meses ou anos.

5. Performance

   Arquivos de log excessivamente grandes podem tornar ferramentas de análise e ingestão de logs mais lentas.

6. Alertas

   A ausência de rotação de logs pode indicar falta de configuração ou adulteração de logs.

## Rotação de Logs na prática

### Sistemas Linux

   A maioria das distribuições Linux usam logrotate, uma utilidade que gerencia a rotação, compressão, e deleta os arquivos de logs. Isso é configurado via ***/etc/logrotate.conf*** e em arquivos individuais em ***/etc/logrotate.d/***.

*Exemplo:*

```
   /var/log/auth.log {
       weekly
       rotate 4
       compress 
       missingok 
       notifempty
  }
```

*Essa configuração significa:*
* Logs são rotacionados semanalmente.
* Somente 4 arquivos são mantidos.
* Logs antigos são comprimidos.
* Rotação é ignorada caso o arquivos esteja vazio.
* Se o arquivo estiver ausente, nenhum erro será exibido.

*Teste manual* 
```
sudo logrotate --debug /etc/logrotate.conf
```

### Sistemas Windows

Os logs e Eventos do Windows rotacionam automaticamente baseados no tamanho dos arquivos ou políticas sobrescritas. Essas configurações podem ser mudadas via Event Viewer.

**Etapas:**
1. Abra o Event Viewer -> Clique com botão direito no registro de log -> Propriedades
2. Configure o tamanho máximo de log(ex: 200MB).
3. Excolha a ação: Sobrescrever eventos, arquivar registros ou parar de registrar logs.

**Verificação do Powershell**

```
Get-EventLog -LogName Security | Measury-Object
```

##  Arquitetura de Política de Retenção

A retenção de logs dependem de diversos fatores:

* Requisitos regulatórios.
* Políticas internas de segurança.
* Capacidade de armazenamento.
* Risco de negócios e criticidade dos sistemas.

### Guia Comum de Retenções

| Tipo de Log | Retenção Recomendada |
|-------------|----------------------|
| Logs e Autenticação (SSH, RDP) | 180 - 365 dias |
| Logs e Segurança (EDR, SIEM) | 1 - 3 anos |
| Logs de acesso à servidores WEB | 90 - 180 dias |
| Firewall, Logs de IDS/IPS | 90 - 365 dias |
| Atividades de Logs de APIs de CLOUDs | 180 - 365 dias |
| Sistemas de regulação/conformidade | 1 - 7 anos |

### Estratégias e Ferramentas de Retenção 

* Centralizar logs em SIEM ou armazenamento dem Nuvem ( Azure Blob).
* Implementar camadas de armazenamento a frio para logs usados com pouca frequência.
* Criptografar logs de arquivos para manter a confidencialidade e integridade.
* Marcar logs com metadados para automatizar o gerenciamento do ciclo de vida.

*Armazenamento frio: tipo de armazenamento otimizado para custo, não para velociddade. O acesso é mais lento, mas oo preço por GB é muito menor.*

## Considerações de Segurança

* Prevenir acesso não autorizado a logs arquivados.
* Monitorar por logs deletados ou alteração de tentativas de acesso.
* Assegurar o encaminhamento de logs continue após a rotação.
* Validar que logs não foram truncados durante a compressão ou arquivamento.

### Exemplo de Encaminhamento de Logs (Syslog Linux):

```
   *.* @192.168.1.10:514
```
