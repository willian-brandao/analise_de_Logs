## Introdução 

Em Threat Hunting, pivotagem significa pegar um ponto de dados(ex: endereço IP, domínio, hash ou nome de usuário) e seguir esses rastros através de múltiplas origens de logs para descobrir informações relacionados ou contruir uma timeline. Isso é uma habilidade fundamental quando se investiga ataques multiníveis, movimento lateral,  ou ativididade de comando e controle. 

---

## Origem de Logs Chave para Pivotagem 

|           Origem            |           Elementos típicos de pivotagem           |
|-----------------------------|----------------------------------------------------|
|        Logs de DNS          |        Domínios de consulta, IPs de clientes       |
|        Logs de Proxy        |    URLs, domínios, métodos, agentes de usuários    |
|        Logs de EDR          | Hashes de arquivos, cadeias de processos pai-filho |
|       Logs de Autenticação  | Nomes de usuários, tipos de login, IPs de Origem   |
|        Logs de Firewall     |        IPs de origem e destino, portas             |
|        Logs de Cloud IAM    |        Ator, ação, recurso acessado                |

---

## Exemplo 1: Domínio Suspeito em Logs de DNS

### Indicador inicial:

Consulta DNS para **cdn-assets-update[.]com** do IP **10.10.5.12**

### Pivotagem:

1. Logs de Proxy: Pesquisar por 10.15.5.12 contatando o domínio - confirmar o comportamento de requisições GET/POST e anomalias de user-agent.
2. Logs de Firewall: Checar o se o tráfego para o endereço IP resolvido(por exemplo, 104.21.11.20) foi permitido na saída.
3. Logs de EDR: Qual processo foi iniciado na consulta de DNS? Frequentemente é **powershell.exe** ou **cmd.exe**.
4. Logs de Autenticação: Quem tem logado todo tempo dentro do sistema 10.10.5.12?

---

## Exemplo 2: Execução Suspeita do Powershell

Indicador Inicial: 

**powershell.exe -enc** visto em Logs de EDR de um host **win-07**.

Pivotagem:
1. Árvore de Processos:O arquivo pai era winword.exe? Como em phishing?
2. Logs de Autenticação: Qual usuário executou isso? Esse usuário logou em algum lugar antes?
3. Logs de Proxy/DNS: Alguma conexão de saída de seguida pela execução?
4. Telemetria de EDR: Algum arquivo foi excluído ou alguma nova rotina foi criada?

## Diagrama de Workflow de Hunting
```
            [Indicator: Suspicious IP]
                      |
           → Firewall logs (verify comms)
                      ↓
            Proxy logs (URL/path/User-Agent)
                      ↓
            DNS logs (who resolved domain)
                      ↓
     EDR logs (which process made the call)
                      ↓
   Authentication logs (who was logged in)

```
A pivotagem recursiva é a fundação real das investigações de threat hunting.
---

## Técnicas Práticas para Pivotagem 

1. Pivotagem baseada em IP
   * Começa com um IP de log de firewall/proxy.
   * Encontrar todos os agentes de usuários e hosts de destino.
   * Voltar ao início: encontrar resoluções DNS para domínio/IP.

2. Pivotagem baseada em Hash (centrada em edr)
   * Começa com hash de arquivo (ex: SHA256 de uma DLL malicioso).
   * Checar todos os endpoints que eles apareceram.
   * Priorizar os processos que deram início a isso.

3. Pivotagem baseada em usernames.
   * Rastrear um usuário através de VPN, RDP, acesso interno.
   * Encontrar escalonamento de privilégio ou movimento lateral.
   * Comparar padrões de URL com famílias de malware conhecidas.(ex: /upload.php, /gate.php)

4. Redirecionamento guiado por comportamento
   * Identificar o tempo de requisição de saída regular em proxy.
   * Cruzar referências de origem com EDR para encontrar processos originais.
   * Correlacionar com histórico de domínio de DNS.

## Ferramentas e Consultas 

### Elastic KQL 

```
dns.question.name : "cdn-assets-update.com"
| join kind=inner (
  process.name : "powershell.exe" AND host.name : "WIN-07"
)
on host.ip
```

### Splunk SPL

```
index=proxy OR index=firewall
| search src_ip="10.10.5.12" OR dest_ip="104.21.11.20"
| stats values(uri) by src_ip, user, timestamp
```

### Sigma Rule Example
```
title: Powershell Invoked After DNS Resolution of Suspicious Domain
detection:
   dns:
      query: "*cdn-assets-updae.com"
   edr:
      process_name: "powershell.exe"
considition: dns and edr within 5m
```

## Armadilhas Comuns

|                     Erros                  |                  Risco                                       |
|--------------------------------------------|--------------------------------------------------------------|
|   Pivotamento sem o contexto de timestamp  |  Pode correlacionar eventos não relacionados                 |
|    Ignorar mascaramento de NAT ou Proxy    |  Conduzir a atribuições falsas de IPs de origem              |
|     Não usar sessões identificadoras       |  Quebra a corrente de eventos em sistemas de multiusuarios   |
|   Olhar demais para autenticações falhas   |  Perder tentativas de preenchimento de credenciais ou sondagem|

## Exemplo de Threat Hunting: Pivotagem de Movimento Lateral

1. Começa com login RDP ( Eventos do windows id 4624, Login tipo 10)
2. Realizar pivotagem nos logs do EDR para analisar quais processos foram executados após o login.
3. Checar cruzamento com logs de DNS para ver se os domínios de saída foram contatados.
4. Olhar os logs de autenticação para o mesmo registro de logs de usuário em outros sistemas.
5. Adicionar enriquecimento de contexto de Geolocalização de IP: essa conta sempre loga de uma localização incomum?
