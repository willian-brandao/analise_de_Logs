# Introdução 

Firewalls representam a primeira linhas de defesa na segurança de rede. Eles controlam o fluxo de rede baseado em regras predefinidas e são responsáveis por bloquear tentativas de acesso não autorizados. Os logs do Firewall são essenciais para visibilidade dentro da atividade de rede e são frequentemente a primeira origem de evidência durante a tentativa de intrusão. 

### Analisando os logs de Firewall permitem que profissionais de segurança:
* Detectar escaneamento de portas e reconhecimento atividade;
* Observar padrão de tráfico de entrada e saída;
* Correlacionar alertas com outras orifgens de dados como Ids, logs de endpoints, logs de proxy.

## Tipos Comuns de Firewall e Formatos de Logs 

|          Tipo Firewall    |        Exemplo           |      Formato de Log            |
|---------------------------|--------------------------|--------------------------------|
|    Hardware Firewall      | Cisco ASA, FortiGate     | Syslog, proprietário           |
| Firewall baseado em host  | iptables, UFW, Windows FW| Texto, CSV, EVTX               |
|    Cloud Firewall         | AWS SG/NACLs, AZURE NSG  | JSON, CloudWatch, Log Analytics|
| Web Application Firewall  | ModSecurity, AWS WAF     | JSON, auditoria de log de texto|

Muitos firewalls corporativos suportam saída de syslog, que fazem ingestão de logs dentro de plataformas de SIEM simples.

## Anatomia de Entrada de logs no Firewall

**Exemplo: iptables logs(Linux, via syslog)**
```
Jan  1 14:45:31 server kernel: [UFW BLOCK] IN=eth0 OUT= MAC=00:15:5d:01:02:03 SRC=192.168.0.10 DST=10.0.0.5 LEN=60 TOS=0x00 PREC=0x00 TTL=64 ID=54321 PROTO=TCP SPT=51515 DPT=22 WINDOW=29200 RES=0x00 SYN URGP=0
```
**Campos analisados:**
* Action: BLOCK
* Source IP: SRC=192.168.0.10
* Destination IP: DST=10.0.0.5
* Protocol: PROTO=TCP
* Source Port: SPT=51515
* Destination Port: DPT=22
* FLAGS: SYN (connection attempt)
**Caso de uso: Tentativa de acesso SSH bloqueado por firewall.**
---
### Exemplo: Entrada de Log de Cisco ASA
```
%ASA-6-106015: Deny TCP (no connection) from 192.168.1.100/45678 to 10.0.0.10/80 flags RST on interface outside
```
* Severidade: 6 (Informacional).
* Tráfego TCP negado (no stateful connection stablished).
* TCP Flag **RST** indicando um reset.
* Tráfego foi bloqueado fora da interface.

## Casos de Uso Comuns

### Detecção de Escanner de Porta
* Alto Volume de conexões negadas para múltiplas portas.
* Tipicamente rápido e sequencial (ex: portas 20-1024)
```
grep "DPT=" /var/log/syslog | awk '{print $NF}' | sort | uniq -c | sort -nr
```
### Tráfego de entrada incomum 
* Logs mostram IPs de origem da internet direcionados a sistema internos.
* Tentativa de acessar serviços incomuns(ex: telnet, NetBIOS, snmp)

### Movimento Lateral Interno 
* Movimento lateral não esperado entre dispositivos.
* Pode indicar uma propagação de malware, reuso de credenciais ou reconhecimento interno.

### Tráfego de saída bloqueado
* Sistemas tentam acessar IPs maliciosos já conhecidos ou portas que não são padrão.
* Exemplo: Tentativas de envio de sinais de malware nas portas 8080 ou 53 (DNS).

---

## Boas Práticas para Registro de Logs

- Registre o tráfego permitido e o bloqueado, especialmente as conexões negadas.
- Assegure que os logs tenham sempre etiquetas de data/hora em UTC para poder correlacionar com outros dispositivos.
- Identifique zonas e interfaces claramente.
- Normalize campos de logs para ingestão em SIEMs.
- Enaminhe logs para um coletor centralizado via Syslog UDP/TCP.

**Encaminhamento de Syslog:**
```
:msg, contains, "UFW" @192.168.1.10:514

```

## Consultas SIEM e Regras de Detecção 

Exemplo no Splunk: Bloqueio de escaneamento de portas detectado. 
```
index=firewall action=blocked | stats count by src_ip, dest_port | where count > 10

```

Elastic Search (KQL)
```
action: "BLOCK" and destination.port >= 0
```


Microsoft Sentinel (KQL)
```
CommonSecurityLog
| where DeviceVendor == "Fortinet"
| where Message has "Deny"
| summarize TotalAttempts = count() by SourceIP, DestinationPort
| where TotalAttempts > 20
```
