## Introdução 

Sistemas de Detecção de Intrusão (IDS) e Sistemas de Prevenção de Intrusão (IPS) são componentes chave nas camadas de estratégia de defesa. Enquanto firewalls focam no controle de tráfego, soluções de IDS/IPS analisam o contexto de tráfego e padrões para ameaças conhecidas ou desconhecidas. 

**IDS**: Detectar e alertar atividade suspeitas porém não as bloqueiam. 
**IPS**: Bloqueia ativamente ou interrompe tráfego malicioso baseado na lógica de detecção. 

Ferramentas IDS/IPS open-source:
* Snort(Cisco): Detecção baseada em assinatura.
* Suricata (OISF): Motor Multithread com capacidade IDS/IPS/NSM.
* Zeek: Monitoramento de segurança, não focado em assinaturas.

---

## Entendendo Logs IDS/IPS 

Logs de sistemas IPS/IDS usualmente incluem:

* Timestamp: quando o evento ocorreu.
* Signature ID: regra que gera o alerta.
* Source/Destination IP and Ports: IPs de origem e destino, portas de origem e destino.
* Protocol and packets details: detalhes dos protocolos usados para uma determinada atividade maliciosa.
* Message/Classification: Pequena descrição da ameaça.
* Severity/Priority: Severidade da atividade maliciosa.

---

## Exemplo: Log de Alerta do Snort 
```
[**] [1:1000001:1] ET SCAN Nmap Scripting Engine User-Agent Detected [**]
[Classification: Attempted Information Leak] [Priority: 2]
06/30-14:22:10.123456 192.168.1.100:58000 -> 10.0.0.20:80
TCP TTL:64 TOS:0x0 ID:1111 IpLen:20 DgmLen:48
***A**** Seq: 0x0  Ack: 0x0  Win: 0x400  TcpLen: 20
```
**Explanação:**
* SID: 1000001 - regra ou de ameaças emergentes.
* Classification - Tentativa de vazamento de informações.
* Traffic: Vindo de sistemas internos para servidor web na porta 80.
* User-Agent detection: Possivelmente um escaneamento de Nmap com script NSE.

## Casos de Usos para Analistas de Segurança

1. Detecção de Reconhecimento
   * Regra gerada por use-agent incomum, dns mal-formado, ou smb probes.
   * Exemplos de Suricata/Snort:
      * Detecção de Nmap.
      * Assinaturas de Masscan.
      * Tentativa de tunelamento DNS.
2. Tentativa de exploração
   * Kits de exploração, padrão de estouro de buffer, detecção de shellcode.
   *  Exemplo: "ET EXPLOIT Possível CVE-2021-44228 Log4j JNDI Lookup"
3. Comunicação de Malware
   * Padrão de sinalização de C2 (ex: requisição HTTP POST recorrente a cada 10 segundos)
   * Assinaturas de ET para famílias de malware(ex: TrickBot, Emotet).
4. Exfiltração de Dados
   * Detecção de saídas grandes sobre portas incomuns.
   * Anomalias em protocolos (ex: HTTP POST com conteúdo binário).
5. Movimento Lateral
   * Sondagem de compartilhamento de administrador SMB/Windows.
   * Uso incomum de RDP ou PsExec interno.

## Redação de Regras de Assinaturas Personalizadas

Exemplo de Regra Snort: Detecção de user-agent do Nmap
```
alert tcp any any -> any 80 (msg:"Nmap NSE User-Agent"; content:"Nmap Scripting Engine"; http_header; sid:1000001;)
```
Regra do Suricata: Padrão de exfiltração de DNS
```
alert dns any any -> any any (msg:"Possible DNS Exfiltration"; dns.query; content:".xyz"; pcre:"/([a-zA-Z0-9]{20,})\.xyz$/"; sid:2022101;)
```
---

### Técnicas de Correlação

 * Enriquecer com Threat Intelligence: Combinar domínios de IP contra feed de threats.
 * Correlacionar por UID: Suricata pode assinar fluxo de UIDs para rastrear sessões.
 * Pivotagem em assinaturas de Id: Alertas de links para as técnicas do Mittre Att&ck.
 * Correlação baseada em tempo: Alinhar alertas de id com logs de endpoints ou firewalls.

## Exemplos de SIEM

### Splunk - Detectar tentativa de Log4j 
```
index=suricata event_type=alert signature="*Log4j*"

```
### Elastic/Kibana - Detectar Sinalização
```
{
  "query": {
    "match_phrase": {
      "alert.signature": "C2 Generic Beacon Detected"
    }
  }
}
```
### Microsoft Sentinel - Gatilho de regra NIDS do Suricata
```
SuricataCL
| where EventType == "alert"
| where Signature contains "Nmap"
```

## Considerações do IDS vs IPS

|      Funcionalidade     |           IDS              |           IPS                |
|-------------------------|----------------------------|------------------------------|
| Ação                    | Somente alertar e detectar | Detectar e bloquear tráfego  |
| Risco                   | Baixo ( sem disrupção      |Alta (possível falso positivo |
| Implantação             | Passivo(SPAN port, TAP)    |Alinhado(no caminho do tráfego|
| Caso de Uso             | Visibilidade e detecção    | Aplicação em tempo real      |

---

## Ajuste e Redução de Falso Positivos

* Suprimir regras barulhentas e irrelevantes para o ambiente.
* Assinaturas personalizadas baseadas em modelos de ameaças internas.
* Usar regras de threshold para evitar fluxo de alertas.
* Monitore a relação enre alertas e ações para o IPS (evite bloquear tráfego legítimo).

Exemplo: Supressão no Snort
```
suppress gen_id 1, sig_id 2010935, track by_src, ip 192.168.1.50
```
