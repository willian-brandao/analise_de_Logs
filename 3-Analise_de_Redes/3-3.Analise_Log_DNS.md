## Introdução 

DNS é um dos serviços mais críticos em redes. Aproximadamente todas as comunicações de redes começam com uma requisição de DNS, transformando logs de DNS em uma mina de ouro para detecção e threat hunting.

Logs de DNS provêem visibilidade em:
* Pesquisas de domínios por hosts internos.
* Indicadores de malware ou comunicação C2.
* Tunelamento de DNS e exfiltração de dados.
* Typo-squatting e acesso de domínios de phishing.

Analisando tráfego DNS pode-se revelar ameaças que evandem firewalls tradicionais ou ferramentas de antivírus.

## Origens Comuns de Logs de DNS

|         Origem            |          Exemplo              |        Formato         |
|---------------------------|-------------------------------|------------------------|
| Logs de Resolvedor de DNS | BIND, UNBOUND, Windows DNS    | Texto, JSON            |
| Sensores passivos de DNS  | Zeek, SecuriyOnion, Suricata  | JSON, TSV              |
| Logs de Cloud             | AWS Route 53, GCP Cloud DNS   | JSON                   |
| Registro de logs de hosts | Sysmon(event id 22), Ferramentas de EDR | EVTX, JSON   |

## Exemplos de Logs

**Logs de Servidor de DNS do Windows (Event Viewer, Logs análiticos)**
```
Query Name: suspiciousdomain.xyz
Query Type: A
Client IP: 192.168.1.105
```

**Logs de DNS do Zeek**
```
1624864302.305429	Cd1nFl3fF8A3LsH0VO	192.168.1.10	53	google.com	A	0	NOERROR	F	0.001234
```
**Campos de Interesse:**
* Timestamp
* Query Name (domínio)
* Query Type(A, AAAA, TXT, etc)
* Client IP
* Response code (NOERROR, NXDOMAIN)
* TTL and answers (optional)

## Casos de Uso para Analistas de Segurança

1. Detectando Domínios Suspeitos ou Maliciosos
   * Domínios com baixa reputação.
   * Domínios de registros recentes(usando feeds de threat intel ou DNS passivo).
   * Infraestrutura C2 conhecida(MISP, OTX, VirusTotal).
2. Identificando Tunelamento DNS
   * Consultas em txt com strings longas codificadas.
   * Número de excessivo de subdomínios(ex: abc123.xyz.c2domain.com)
   * Frequência de consultas excepcionalmente alta para um único domínio.
3. Detecção de Malware ou Kits de exploração
   * Padrão de domínio DGA(ex: strings geradas ramdomicamente como *sdfklweu.biz*)
   * Domínios resolvidos antes da execução do payload.
   * Requisições de DNS feitas fora do horário de expediente a partir de estações de trabalho de usuários.

## Técnicas de Detecção 

Detecção baseadas em regras no Zeek ( exemplo com a heurística do tunelamento de DNS):
```
event dns_request(c: connection, query: string)
{
  if ( query like /[a-zA-Z0-9]{30,}/ )
    print fmt("Possible DNS tunneling: %s from %s", query, c$id$orig_h);
}
```

Alerta de Suricata para DNS sobre porta incomum
```
alert udp any any -> any !53 (msg:"Suspicious DNS Query on non-standard port"; dns.query; content:".com"; sid:100013;)

```
Regra Sigma para DNS via Sysmon
```
detection:
  selection:
    EventID: 22
    QueryName|contains: ['.xyz', '.top', '.club']

```

## Exemplo de Threat Hunting 

Procurar por novos domínios de registros
```
index=dns_logs query=* 
| lookup domain_age_lookup domain AS query OUTPUT first_seen
| where now() - first_seen < 259200  // domain < 3 days old
```

Procurar por Consultas de alta frequência
```
index=dns_logs 
| stats count by src_ip, query 
| where count > 100
```
Detectar Padrões semelhantes a DGA
```
def is_dga(domain):
    import re
    return bool(re.match(r'^[a-z0-9]{15,}\.com$', domain))

```

## Boas Práticas para Registro de Logs de DNS

* Permitir registro full de DNS em resolvedores internos.
* Registrar logs de consultas e respostas.
* Criar etiquetas de tempo em UTC e incluir metadados de clientes.
* Armazenar logs em um SIEM com enriquecimento.
* Aplicar feeds de Threat Intelligence para consultas de DNS.
---
## Enriquecimento e Correlação
* Pesquisa de reputação: usar feeds como Cisco Umbrella, OTX, ou Virus Total.
* DNS Passivo: Determinar quando foi a primeira aparição do domínio.
* Dados do WHOIS: Inspecionar datas de registro e informações registradsas.
* Mapear com Mittre ATT&CK:
   * T1071.004 - Camada de Aplicação: DNS.
   * T1046 - Escaneamento de serviço de redes.
   * T1095 - Protocolo de camada não aplicativa (DNS C2 personalizado)
---
## Resumo 

Logs de DNS são uma fonte poderosa de detecção e inteligência. Enquanto DNS é um protocolo necessário e legítimo, e também é frequentemente usado indevidamente por agentes maliciosos para stealthy comando e controle furtivos e exfiltração de dados.  A operação de umtime de segurança maduro pode ter visibilidade dentro da atividade DNS e monitorar ativamente domínios suspeitos, padrões de tráfego e sinal de abuso.
