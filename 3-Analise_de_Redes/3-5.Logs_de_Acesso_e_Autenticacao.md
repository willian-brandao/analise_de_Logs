## Introdução

Logs de acesso e autenticação são fundamentais para rastrear atividades, identificar anomalias e detectar potenciais incidentes de segurança como ataques de força bruta, roubo de credenciais, movimento lateral e escalonamento de privilégio. Esses logs servem como o fundamento para trilhas de auditorias, monitoramento de compliance, e identificação centralizada de detecção de ameaças.

* Logs de Segurança do Windows.
* Linux /var/log/auth.log.
* Controles de domínio do AD.
* Gateways de VPN.
* Plataformas de SSO (Okta, Azure AD, Keycloak).
* Logs do Cloud IAM (AWS CloudTrail, GCP Audit,Logs do Azure Sign-in).
* Web Application e APIs com autenticação de endpoints.

 ---

## Campos Chave em Logs de Autenticação 

|             Campo              |              Descrição                                  |
|--------------------------------|---------------------------------------------------------|
| Timestamp                      | Data e tempo do evento de login                         |
| Username                       | Conta usada durante a autenticação                      |
| IP origem                      | Origin da tentativa de login                            |   
| Host de destino                | Sistema ou serviço que está sendo acessado              |
| Tipo de autenticação           | Senha, MFA, Certificado, Kerberos, NTLM                 |
| Saída do Evento                | Sucesso, Falha, Bloqueio                                |
| Id de Evento / code            | Identificar plataformas específicas                     |
| Tipo de login                  | Interativo, Rede, RDP, Batch                            |
| Id de Sessão                   | Correlacionar eventos relacionados dentro de uma sessão |
| Reação da Falha                | Credenciais inválidas, contas desativadas, etc          |

## Casos de Uso para o Time de Segurança 

1. Detecção de ataque de Força Bruta
   * Múltiplos tentativas de login falhas em espaço curto de tempo.
   * Tentativas incrementais usando diferentes usernames.
   * Logins em horários e de origens incomuns.

2. Roubo de Credencial
   * Logins falhos de vários IPs destinados a uma mesma conta.
   * Usar ferramenta de automação (ex: Hydra, Metasploit)

3. Escalonamento de Privilégio
   * Logins para contas restritas.
   * Logins de conta seguidos de acesso a recursos privilegiados.

4. Movimento Lateral
   * Logins com sucesso através de múltiplos hosts dentro de um curto espaço de tempo.
   * Login tipo 3(rede) ou tipo 10(rdp) em consequência.

5. Padrão de Acesso Incomum
   * Logins de geolocalização estrangeira ou fora do horário de expediente.
   * Desafios de MFA acionados ou negados.
   * Acesso a contas para uso de serviços que não são comuns.

## Técnicas de Detecção 

### Regra Sigma - Login Falho de um IP externo
```
detection:
  selection:
    EventID: 4625
    SourceNetworkAddress|ip: ['not in private ranges']
  condition: selection
```
### Splunk - Múltiplas Falhas por nome de usuário
```
index=wineventlog EventCode=4625
| stats count by Account_Name, Source_Network_Address
| where count > 10
```
### Elastic - Acesso SSH com sucesso em horário fora do expediente
```
process.name: "sshd" and message: "*Accepted*"
and @timestamp not between "08:00:00" and "18:00:00"
```

## Exemplos Avançados

Caso de Uso: Movimento Lateral via RDP

1. Detectar Eventos com id 4624 com tipo de login 10 (Interatividade remota).
2. Agrupar por nome de usuário e tempo.
3. Alertar se o mesmo nome de usuário estiver logado em 3 ou mais dispositivos na rede ao mesmo tempo.

Caso de Uso: Comportamento Suspeito da conta de serviço

1. Conta de serviço com logons interativos (tipo 2).
2. Logins de IPs externos ou em horários inesperados.

Caso de Uso: Detecção de Viagens Impossíveis
1. Usuário com registro de log do Brasil, depois de 5 minutos conectado a algum lugar na europa.
2. Requer correlação de *IP de Origem* + *Geolocalização* + *Timestamp*.

## Consultar de Threat Hunting 

Logins de Admin Suspeitos 
```
index=wineventlog (EventCode=4624 OR EventCode=4625)
| search Account_Name IN ("admin", "administrator", "root")
```

Contas com múltiplos bloqueios 
```
index=wineventlog EventCode=4740
| stats count by Account_Name, Source_Network_Address
```

## Boas Práticas

1. Centralizar autenticação de logs de todos os sistemas e serviços.
2. Permitir auditoria de registro de logs detalhada.
3. Aletar sobre o alto risco de comportamento de autenticação.
4. Aplicar contexto: mapear tentativas de login para perfis de usuários e comportmento esperado.
5. Enriquecer logs com geolocalização e correlação com endpoints.
